# URL Shortener

A small URL shortening API built with [Encore.ts](https://encore.dev/docs/ts). Send it a long URL and it returns a short ID; look up the ID to get the original URL back. Every short URL expires **500 seconds** after it is created.

The app is a single Encore service (`url`) backed by a PostgreSQL database that Encore provisions automatically, both locally and in the cloud.

## How it works

```
POST /url  {"url": "https://encore.dev"}
   │
   ├─ generate a random 8-character ID (6 random bytes, base64url-encoded)
   ├─ INSERT (id, original_url, expires_at = NOW() + 500s) into the `url` table
   └─ return {"id": "FNZZoO_K", "url": "https://encore.dev", "expiresAt": "..."}

GET /url/FNZZoO_K
   │
   ├─ SELECT original_url, expires_at FROM url WHERE id = 'FNZZoO_K'
   └─ return {"id": "FNZZoO_K", "url": "https://encore.dev", "expiresAt": "..."}
      (or 404 "url not found" / 404 "url has expired")
```

Note that `GET /url/:id` returns the original URL as JSON; it does not issue an HTTP redirect.

Expired URLs are never deleted from the database; they stay in the `url` table and lookups simply report them as expired. Expiry is evaluated against the database clock (`NOW()`).

## Project layout

| Path | Purpose |
|---|---|
| `encore.app` | Encore app manifest (app ID `url-shortener-byvi`) |
| `encore.service.ts` | Declares the `url` service |
| `url.ts` | The `shorten` and `get` API endpoints, the `url` database, and the 500-second TTL (`URL_TTL_SECONDS`) |
| `migrations/001_create_tables.up.sql` | Creates the `url` table (`id TEXT PRIMARY KEY`, `original_url TEXT NOT NULL`) |
| `migrations/002_add_expires_at.up.sql` | Adds `expires_at TIMESTAMPTZ NOT NULL`; existing rows get 500 seconds from when the migration runs |
| `url.test.ts` | Vitest tests for shortening, lookup, the 500-second TTL and expired/unknown IDs |
| `encore.gen/`, `.encore/` | Generated by the Encore CLI; do not edit |

## API

### `POST /url` — shorten a URL

Request body:

```json
{ "url": "https://encore.dev" }
```

Response:

```json
{ "id": "FNZZoO_K", "url": "https://encore.dev", "expiresAt": "2026-10-03T16:30:27.821Z" }
```

### `GET /url/:id` — look up a short ID

Response:

```json
{ "id": "FNZZoO_K", "url": "https://encore.dev", "expiresAt": "2026-10-03T16:30:27.821Z" }
```

Errors:

| Case | Response |
|---|---|
| Unknown ID | `404` — `{"code": "not_found", "message": "url not found"}` |
| Expired (more than 500 s old) | `404` — `{"code": "not_found", "message": "url has expired"}` |

## Getting started

### Prerequisites

- [Encore CLI](https://encore.dev/docs/ts/install)
- Node.js 20+
- Docker (Encore uses it to run PostgreSQL locally)

### Install and run

```bash
npm install
encore run
```

The API is served at <http://localhost:4000>, and Encore's [local development dashboard](https://encore.dev/docs/ts/observability/dev-dash) (API explorer, traces, database info) is at <http://localhost:9400>.

Try it out:

```bash
curl http://localhost:4000/url -d '{"url": "https://encore.dev"}'
# {"expiresAt":"...","id":"FNZZoO_K","url":"https://encore.dev"}

curl http://localhost:4000/url/FNZZoO_K
# {"expiresAt":"...","id":"FNZZoO_K","url":"https://encore.dev"}

# ...more than 500 seconds later:
curl http://localhost:4000/url/FNZZoO_K
# {"code":"not_found","message":"url has expired","details":null}
```

To compile, boot and smoke-test the app in one step:

```bash
encore check 'curl /url -X POST -d "{\"url\":\"https://encore.dev\"}"'
```

## Testing

```bash
encore test
```

`encore test` sets up an isolated test database and then runs Vitest. Running `npm test` directly skips that infrastructure setup, so the database test will not work that way.

## Deployment

Pushing to the Encore remote deploys the app to Encore Cloud:

```bash
git push encore
```

Monitor deployments and find environment URLs in the [Encore Cloud Dashboard](https://app.encore.dev). Encore can also deploy into your own AWS or GCP account.
